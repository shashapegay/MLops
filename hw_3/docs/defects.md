# Найденные и исправленные дефекты

## 1. Данные могли попасть в Git

**Симптом.** `git add .` добавлял `data/*.jsonl`, а `git log --stat` показывал
крупные файлы.

**Причина.** В `.gitignore` не было `data/`.

**Исправление.** `data/` добавлен в `.gitignore`. Сами JSONL объявлены как
`outs` DVC; train, val и test теперь перечислены явно.

**Проверка.** `make check`, пункт 1: `git ls-files data/` должен вернуть 0.

---

## 2. Смена v1 → v2 не обязана была пересчитывать collect

**Симптом.** После изменения `collect.version` DVC мог сообщить, что
пересчитывать нечего.

**Причина.** В `dvc.yaml` у `collect` не было зависимости от секции
`collect` в `params.yaml`.

**Исправление.** В stage `collect` добавлено:

```yaml
params:
  - collect
  - paths.raw
```

Теперь смена `v1`/`v2` меняет вход стадии. Версии также различаются объёмом:
1200 против 2400 строк до clean.

**Проверка.** `make check`, пункт 4: MD5 `data/clean.jsonl` и `rows_in`
должны отличаться после переключения v1 → v2.

---

## 3. Row-wise split создавал leakage

**Симптом.** Одна группа могла оказаться одновременно в train и test.

**Причина.** Исходный `row_split()` случайно перемешивал отдельные строки.

**Исправление.** `src/split.py` теперь сначала собирает строки по
`normalize_group(topic)`, распределяет **целые группы**, а затем пишет
train/val/test. Проверка контаминации вынесена в отдельную DVC stage.

**Проверка.** `make contamination` / `make check`, пункт 5:
`пересечение по группам = 0`.

---

## 4. Near-duplicate проход отсутствовал

**Симптом.** Два почти одинаковых вопроса проходили clean. Тест из
`make check` специально меняет пробелы и нумерацию вариантов.

**Причина.** После exact dedup был пустой `near`-set, то есть фактически
работала только точная дедупликация.

**Исправление.** Добавлен второй проход `near_duplicates()` после exact dedup.
Он использует MinHash + LSH с теми же параметрами, что и contamination.

**Число проверки.** В fixture `make check` есть один точный дубль и один
near-duplicate. Проверка ожидает `dropped_exact_dup >= 1` и
`dropped_near_dup >= 1`.

---

## 5. Diversity был предупреждением, а не гейтом

**Симптом.** Вырожденный набор из 1200 строк мог пройти pipeline с сообщением
«предупреждение».

**Причина.** `src/diversity.py` печатал нарушения, но завершался с кодом 0.

**Исправление.** При непустом списке `violations` стадия теперь пишет
диагностику и завершает работу с кодом 1.

**Число проверки.** Fixture содержит 1200 строк с одним system prompt и одной
группой; должны одновременно сработать несколько diversity-порогов.

---

## Дополнительная проверка: отдельная contamination stage

Исходный split вычислял contamination внутри себя. Это не заменяет отдельный
гейт: split мог быть собран вручную или восстановлен через DVC checkout.

Поэтому добавлена самостоятельная DVC stage:

```text
split -> contamination
```

Она пишет `metrics/contamination.json` и падает при любом пересечении.
